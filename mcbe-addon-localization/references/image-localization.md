# 图片本地化（贴图内文字）

guidebook、教程 UI、成就图标、告示牌贴图上直接印了英文。步骤 6 处理这一层。

**本文件不绑定任何具体模型、本地路径或软件包。** 每台电脑装的东西不一样，
执行前先按 [环境探测](#环境探测) 确认能力，再选方案。

---

## 共同硬约束（任何方案都必须满足）

| 约束 | 说明 |
|------|------|
| **像素宽高完全一致** | 含非正方形贴图。MCBE 贴图大量非 16:16，模型常擅自改画幅 → 尺寸不符 **一律不写回** |
| **只改文字** | 不动画风、边框、背景、图标、UV 布局、光影 |
| **保留 alpha** | 半透明/全透明 UI 贴图经重绘常变成不透明黑底，这是最常见的翻车点 |
| **格式保持 PNG** | 不要为了"体积小"转 JPG，会丢 alpha 且贴图边缘出现噪点 |
| **先备份** | 原图复制到同目录 `_backup/`，文件名保持一致便于回滚 |
| **只处理用户点名的图** | 不要"顺手"全包重写贴图 |

写盘前的硬断言：

```python
assert out.size == src.size, f"尺寸不一致：{out.size} != {src.size}"
```

---

## 方案选择

| 情况 | 选 |
|------|-----|
| 文字较多、要求整体画风统一、能接受轻微重绘 | **A** |
| 像素画 / UI 贴图 / 图标 / 要求像素级保真 | **B** |
| 方案 A 输出尺寸或 alpha 对不上原图 | **B** |
| 手上没有可用的图生图模型 | **B**（OCR 取框可用多模态模型，不依赖任何本地安装） |
| 贴图文字只是占位英文、不影响理解 | 跳过，如实告知用户 |

## 方案 A：图生图 / 局部编辑模型（整图或分块重绘）

### 能力要求（不指定模型）

需要一个**接受参考图输入**且**能按指令保留画幅**的模型。可能是：

- 本地：`Qwen-Image`、`FLUX.1 Kontext`、`SDXL + inpaint`、`ComfyUI` 工作流
- 远程服务：Gemini、GPT-Image edit、Seedream、豆包/即梦等

以上只是举例。**提示词契约本身与模型无关**——凡支持"参考图 + 指令编辑"的模型都能用，
换模型只换调用方式，不改提示词结构。

### 使用顺序

1. 询问使用者手上有哪些模型/服务（本地权重路径、ComfyUI 工作流、或云端 API）
2. 按 [环境探测](#环境探测) 确认可用性
3. **没有 → 转方案 B**，不要硬凑，也不要"先跳过等以后再说"而不告知用户

### 分块编辑优于整图重绘

整图重绘时模型会把没文字的地方也重画一遍，风格必然漂移。可靠做法是 **crop → 编辑 → 按原坐标贴回**：

1. 用 OCR（或人工看图）确定每个文字块的 bbox
2. 只把 bbox 区域（外扩 2–4 px 留边）单独送去编辑
3. 贴回原图时使用 **原图未改动的像素**，只有文字块区域被替换

这样像素级保真，且模型要重绘的面积小得多，漏字概率也低。

 guidebook 一整套图要一起处理时，**所有图用同一份提示词**，否则风格不统一。

### 失败模式与对策

| 症状 | 原因 | 对策 |
|------|------|------|
| 输出尺寸变了 | 模型按自身偏好重采样 | **不写回**，转方案 B |
| 透明底变黑底 | 模型不保留 alpha | 提示词显式要求；仍不行则弃用 |
| 画风被重绘 | 整图重绘 | 改分块编辑，只编辑文字区域 |
| 漏字、多字、串行 | 图像模型文字渲染本就不可靠 | 先 OCR 出完整文字清单，逐块编辑；仍不行转方案 B |
| 字形/字重漂移 | 模型重新设计了字体 | 同上；像素级要求一律走方案 B |
| 送多张大图很慢或显存爆 | 条件图预处理开销大（模型内部本来就会 resize） | 参考图缩到 **约 1024 宽**再送；但见下方「尺寸纪律」 |
| 同一批图风格忽变 | 每次独立生成 | 固定 seed、固定风格描述、同一批次处理 |

### 尺寸纪律（最容易搞错的一条）

缩图是为了**省显存/时间**，不是为了产出小图。

- 送给模型的可以是缩到 ~1024 宽的副本
- **但写回磁盘的必须是原分辨率**。如果模型只能按输入尺寸输出、拿不回原图分辨率，
  那就**不要写回**——拉伸放大只会得到糊图，比不汉化更糟
- 这种情况直接转方案 B

## 方案 B：OCR → 擦除 → 写回（可选方案，默认不动其它像素）

贴图上只有文字要改时，这条路比让模型重绘整张图更可靠，也**不依赖任何特定模型**。

### 流程

```
备份 → 取文字块(bbox) → 逐条翻译 → 擦除原字 → 渲染译文 → 尺寸断言 → 肉眼验收
```

#### 1. 备份

原图复制到 `_backup/`。

#### 2. 取文字块（bbox）

任选一种，**按环境探测结果决定**：

| 方式 | 依赖 | 优点 |
|------|------|------|
| **多模态模型直接读**（推荐默认） | 无，你手上就有 | 零安装，能同时给出文本 + bbox + 字体/颜色描述 |
| `tesseract` | 需装 | 印刷体英文快，TSV 直接带 box |
| `PaddleOCR` | `pip install` | 中英混排、竖排好 |
| `Surya` | `pip install` | 美术字、斜体、装饰字体好 |
| 人工标注 | 无 | 文字极少时最快最准 |

提示词见 [translation-prompts.md](translation-prompts.md#ocr-取文字块-bbox)。

bbox 格式统一为 `[x1, y1, x2, y2]`，**原图像素坐标**，左上角为原点。

#### 3. 翻译

逐条走 `.lang` 同样的规则：只译文字、保留专有名词一致性、数字与单位原样。

#### 4. 擦除原字

- 简单背景：取 bbox 周围一圈的中位色填充矩形
- 渐变/纹理背景：局部 inpaint，或直接把该块按背景纹理复制填充
- 宁可 **多留 2–4 px 边距**，残留半截字母比留白更难看

#### 5. 渲染译文

- **必须有 CJK 字体**，否则中文全是豆腐块（各平台字体见下）
- 字号按 bbox 高度换算，留 10%–15% 内边距
- **译文比原文长时要缩字号或折行**，绝不能溢出 bbox 压到旁边图案
  - CJK 字面比拉丁字面宽得多，按 **字数** 而非字符宽度估算更准
- 颜色从原文字块采样；对齐方式（左/中/右）跟原图一致
- 描边/阴影：美术字常有描边，取样后判断要不要补，否则译文会"飘"

#### 6. 尺寸断言 + 验收

```python
assert out.size == src.size
```

- 放大截图逐块看：有没有溢出、残影、豆腐块、错别字
- 透明贴图：确认没在透明区域写入不透明像素

### CJK 字体（缺了必翻车）

| 平台 | 字体 |
|------|------|
| Windows | `C:\Windows\Fonts\msyh.ttc`（微软雅黑）、`simhei.ttf`（黑体）、`simsun.ttc` |
| macOS | `/System/Library/Fonts/PingFang.ttc`、`/System/Library/Fonts/STHeiti Light.ttc` |
| Linux | `fonts-noto-cjk` / `fonts-wqy-zenhei`，通常在 `/usr/share/fonts/` 下 |

找不到可用中文字体时：让使用者装一个，**或**直接产出"只有译文 JSON、贴图未改"的半成品并说明。
不要交付满是豆腐块的贴图。

### 方案 B 的坑

| 坑 | 表现 | 对策 |
|----|------|------|
| 缺 CJK 字体 | 豆腐块 □□□ | 上表先确认 |
| 擦除不干净 | 原字残影 | 外扩边距；必要时改用局部重绘 |
| 译文溢出 bbox | 压到旁边插画 | 缩字号 / 手动折行 |
| 输出 JPG | 丢 alpha、边缘噪点 | 一律 PNG |
| 只改了 alpha 层 | 看不见变化 | 全程 RGBA 操作，合成时确认 alpha 未被丢弃 |

## 环境探测

**不要假设使用者装了什么。** 步骤 6 开始前先确认：

| 需要的能力 | 怎么确认 | 缺失怎么办 |
|-----------|---------|-----------|
| 图生图 / 局部编辑模型 | 直接问使用者（本地权重？ComfyUI？云端 API？） | 转方案 B |
| Python + Pillow | `python -c "import PIL; print(PIL.__version__)"` | 提示安装；或只用多模态模型出图，不做像素处理 |
| CJK 字体 | 看字体目录（上表） | 中文会变豆腐块，必须先解决 |
| `tesseract` | `tesseract --version` | 用多模态模型取框 |
| `PaddleOCR` / `Surya` | `python -c "import paddleocr"` | 同上 |
| `node` | `node -v` | 仅步骤 3/3b 的 `node --check` 需要，缺失时靠人工核对括号 |

**通用性纪律：**

- 本 skill 的文档与提示词里**不写死模型名、本地权重绝对路径、Python 包版本号**
- 写具体实现时把这类信息做成 **可配置项 / 探测结果**，而不是文档正文
- 探测不到就如实告诉用户"本机缺 X，可选方案有 A/B"，不要默默跳过
